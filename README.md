# 拾题 DraftDesk 2

**社区版 · Early Preview**。面向个人的自托管研究与选题工作台，适合开发者和创作者试用、改进。真实模型输出质量与长期定时运行仍在验证中；当前不提供多租户、支付或公网登录保护，请保持本机访问。

一个个人优先、证据驱动的智能选题工作台。内置研究与 Hermes / OpenClaw 等外部工具使用相同的数据协议：资讯 → 证据 → 观点 → 可执行选题 / 应用实验。

## 启动

安装并启动 Docker Desktop 后，在项目目录运行：

```sh
git clone https://github.com/x-rush/draftdesk.git
cd draftdesk
docker compose up -d --build
```

正式本机地址 http://127.0.0.1:5173 。`start.cmd` 启动，`stop.cmd` 停止，`verify.cmd` 运行校验。宿主机无需 Node、Python、数据库或全局环境变量。需要换本机端口时，把项目根目录 `.env.example` 复制为 `.env` 修改 `DRAFTDESK_PORT`。

**升级**：`git pull` 后执行 `docker compose up -d --build`，数据库在 named volume `draftdesk-data` 中不受重建影响；有数据迁移时会随启动自动完成，且**任何待执行迁移前会自动留保险丝快照**（`data/snapshots/`，保留 3 份）。日常备份已自动化：janitor 每日 `VACUUM INTO` 快照到 `backups/`（保留 14 份），恢复即用最新快照替换 volume 中的 `draftdesk.sqlite`。

Next.js App Router / React / TypeScript 提供同源网页与 API；研究任务循环并入应用进程（单进程单 SQLite 连接，2026-10 起 worker 容器已移除），SQLite WAL 保存任务、证据、结果与会话。数据库在 Docker named volume `draftdesk-data` 中，容器重建不丢数据；每日自动快照到 `backups/`（保留 14 份），大版本迁移前自动留保险丝快照到 `data/snapshots/`（保留 3 份）。电脑和 Docker 关闭时不采集，重启后只补当天到期任务。

## 首次使用

1. 模型与设置：填写百炼 Base URL、账号已开通的模型标识和 API Key，保存后测试模型连接。`.env.example` 使用 `qwen3.8-flash`；请以自己账号的可用模型为准，不预设免费额度。这里需要百炼 API Key，不是阿里云 AccessKey ID/Secret。两把密钥的申请步骤、填写位置（页面或环境变量）与常见报错见[密钥获取与配置指南](docs/api-keys.md)。
2. 数据源：AIHOT 精选/产品动态 RSS、百度热搜、Google Trends 地域热榜、GitHub Trending、Hacker News Top、Product Hunt 新产品 Feed、GitHub 仓库搜索和 Tavily；支持自定义公开 HTTPS RSS/Atom。B站热门与微博热搜走官方公开接口（内置、匿名可用）；DailyHotApi 聚合补充知乎、抖音、头条、贴吧、掘金（快手上游仍失败，默认停用）；SearXNG 元搜索与 RSSHub（复活已下线 RSS 源）、Redis（缓存与向量事件线）均随主 compose 一并启动，无需额外步骤。可在「数据源」逐个检测连接，按需启用并加入研究策略；原平台链接和榜单更新时间会保留，过期或无效榜单会报错。网页搜索三档后端：Tavily 先行 + SearXNG 补位（缺省，不配 Key 也能搜索）、仅 Tavily、仅本地 SearXNG；即时热榜的热度不作为跨天增长率。完整操作与排障见[数据源配置指南](docs/data-source-configuration.md)，各来源状态见[热榜来源说明](docs/hotlist-sources.md)。
3. 分析口径（原「研究策略」）：定义受众、目标、关键词、域名、排除词、回看天数与预算，供每日 01:00 全量采集与外部 Agent 语义处理读取（external 模式下分析由外部 Agent 执行，内置手动/定时分析已停用）；已有 OpenClaw／Hermes 等个人助理的用户可以关闭内置定时，改用[外部接入](#外部智能体)让 Agent 自主搜罗回传，避免两条路径重复消耗。
4. 创作活动：在自己的 Chrome / Edge 登录 B站、抖音、快手、小红书创作者中心，打开工作台提供的开源扩展即可进入该平台活动页并采集。扩展默认将活动包送到本机工作台，保留原始快照与历史；也支持 JSON 导出／导入。可对命中关键词的线索单独运行 AI 初筛，查看相关性、缺失证据和条件性内容方向；这不是活动有效性或参与资格证明。过期、未知截止时间和只有摘要的活动不会进入正式推荐分析。新版采集包记录扫描范围；旧包和有限页数采集不能证明已抓全平台最新活动。只有活动中心链接而无单条规则链接的结果需按标题回原平台核对。参见 [四平台活动采集说明](docs/creator-activities.md)。
5. 运行记录：查看来源失败、任务步骤、模型调用和用量。默认关闭每日定时，可按北京时间启用。
6. 每日发现：阅读个人影响、证据、未知项、下一步，收藏/编辑/讨论，再决定内容创作。

左侧菜单按「发现与创作」「机会观察」「研究与设置」分组，所有入口保持可见。「每日发现」首页直接显示近 14 天原始热点、通过检查、待验证、已否决、来源读取失败和失败任务的数量，点击数字即可进入对应列表；分析结果默认同时显示通过检查与待验证，已否决单独筛选，避免把不同质量状态混为推荐。首页的本轮待观察与来源覆盖只对应最近一次研究。独立的「热点列表」汇总最近 14 天各次内置研究、采集预览和独立榜单快照的原始标题；可按来源、批次与筛选状态查找曾被排除或未入模的条目，并手动刷新某个已启用的热榜来源。榜单标题不是 AI 推荐、已证实事实或增长率，也不代表全网覆盖。详细口径见[数据源配置指南](docs/data-source-configuration.md)。

「采集覆盖」可先选研究策略，点击“只采集预览 · 不调用 AI”，检查最多三个已启用的非网页搜索来源实际读到、命中和选入的条目，再决定是否运行付费分析。预览不能代表全网覆盖，热榜即时指数也不能单独证明增长。活动列表默认显示当前可参与的通过检查与待验证条目，两种状态分别标注；时间未知、已结束和已否决活动可用筛选器回看。只有通过检查的记录才属于推荐。

模型连接与网页搜索分别验证：用「测试搜索」按当前后端实测（SearXNG 零成本；Tavily 消耗一次 basic 额度；混合档两项都测，Tavily 未配置不算失败）。模型可调用不代表搜索已接通，测试会消耗对应供应商额度。

没有真实来源时不生成示例新闻；没有密钥时仍可使用外部证据导入、查看和编辑。启用模型功能必须完成真实连接。

## 研究质量

1.2 增加按研究方向扩展查询、总预算内最多两次定向补证、推荐/待验证/已否决分层、事件更新关联和指标快照。默认列表不展示已否决内容，可在质量筛选中单独查看。没有新增或合适材料的任务会完成并显示“无推荐”，来源异常仍显示失败。

研究详情中的“事件与指标历史”显示同事件关联及原始指标。只有明确周期、相同来源/主题/地域/单位的精确值才进行对比；分桶数据不计算增长率。事件合并使用保守的链接、标题或高相似文本匹配，不保证识别所有改写转载。已有数据升级时可运行 `docker compose exec app npx tsx scripts/backfill-history.ts`，只重建历史索引，不补造时间序列。

资讯、趋势、应用研究与质量审稿 Skills 已升级到 v1.3；证据整理为 v1.2，外部提交 Skill 为 v1.1（数据协议仍为 v1.0）。各任务加载版本化参考资料，来源与许可可追溯。内置 7 个语义评测场景及旧版/新版对照工具，使用方法见 `evals/README.md`。没有真实模型评测结果时不展示虚构通过率。

研究详情增加“证据缺口与下一步”，分别检查原始指标、用户问题原话、替代方案、付费行为和关键事实引文，并提供可复制补查词。候选材料不等于事实认证；缺口会进入后续研究的补查与审核流程，仍受原有预算约束。实现与验证边界见 [低评分能力优化记录](docs/low-score-improvements.md) 和 [2026-09-25 全站验收](docs/archive/qa-2026-09-25.md)。

每次任务按版本加载 Skills：证据整理 → 资讯选题 / 趋势 / 应用专项分析 → 独立审稿。结构不合格最多修复一次，总次数与预算仍受约束。硬检查会标记未知引用、虚构引文、单来源、未知发布时间、缺趋势指标或缺用户需求来源。待审结果仍可查看，只有通过当前检查的资讯/选题可手动公开。

趋势类策略的采集批次支持**语义初筛**（默认开启，审查台「内置 AI 参与开关」的 triage 档位可关）：内置 AI 对规则放行的候选做语义归类（同一事件跨源并为组）、注意力判级（强/潜力/无 + 理由）与双线草案（多平台内容角度 + web/app 配套缺口），研究名额按组分配——判「无注意力」的纯体育/时政/民生条目不占名额；机会引擎按组只产应用缺口卡（内容线选题走大纲链路，不出机会卡）。判级理由与组归属随候选进入「待观察线索」页可查。

规则检查和第二次模型审核不等于事实认证。全文未获取时只使用摘要，不声称亲测。不把媒体转载当独立需求样本、不把 Stars/热榜当收入、不把美国热词当中国需求。框架不保证模型每次输出优秀，真实效果应由自己的资料集持续评测。

## 外部智能体

外部接入是**通用能力**，不绑定特定产品：工作台提供版本化的研究指导（Skills 包、搜索计划、JSON Schema 和收件协议），任何能执行提示词、调用 HTTP 的外部 Agent 都能接入——由它按工作台导出的策略自主搜罗、整理，并在自己的调度能力下定时把结果回传，替代内置研究与整理管线。内置管线仍是默认路径（零额外组件）；两者二选一即可，同时在跑会重复消耗模型额度。OpenClaw 与 Hermes 只是本机实测过的样例，不是依赖。

“外部接入”提供 Agent / 运行位置 / 研究模式向导，生成不含密钥的配置提示词。用户把提示词交给自己的 Agent，由它检查环境、安装或读取 Skill、配置已授权搜索工具，并报告缺项；模型与提交令牌由用户在该 Agent 的安全环境中自行处理。工作台提供协议预检和收件状态，不远程替用户修改 Agent 配置。预检不入库、不调用工作台模型。收件箱关联分析状态与产物，相同回执和策略重复点击不会重复创建任务。详细流程见 [接入说明](docs/external-onboarding.md)。

在“外部接入”创建专用提交令牌，下载 Skills 包和 JSON Schema。令牌只用于 `POST /api/v1/intake`，可以单独撤销，服务端只保存散列。外部提交默认待审且私有；不会自行触发付费研究。

外部 Agent 也可以**读取并消费**工作台已搜罗的数据：创建连接时勾选「只读访问」与「消费标记」，令牌即可访问只读 REST（`/api/v1/agent/hotspots|evidence|artifacts|stats`，热榜、证据摘要、带质量标签的选题产物）、消费标记（`POST /api/v1/agent/consume`，默认 dryRun、可撤销，已处理条目不再计入首页计数）与内置 MCP 端点（`POST /api/v1/mcp`，五个只读工具）；只支持本地 stdio MCP 的运行器可用 `scripts/mcp-bridge.mjs` 桥接。三类权限按令牌隔离、互不越界。external 模式下，approved 选题的第一版大纲也由外部 Agent 按「平台 × 题材」双标注提交（见[外部 Agent 接入指南](docs/agent-integration.md)「大纲提交」节）。分步操作（令牌、各运行器配置示例、排障）见[外部 Agent 接入指南](docs/agent-integration.md)，协议细节见[接入说明](docs/external-onboarding.md)。

```sh
export DRAFTDESK_URL=http://127.0.0.1:5173
export DRAFTDESK_TOKEN=你的提交令牌
python skills/draftdesk-submit/scripts/submit.py research.json
```

环境变量只在运行工具的终端/容器配置，不必污染系统环境。协议例子见 `skills/draftdesk-submit/references/intake-example.json`。同一批次稳定使用 submissionId，重复提交不重复写入；同 ID 不同内容返回 409。

技能安装路径由各运行器决定，指导本身与 Agent 无关：已实测样例中 Hermes 放 `~/.hermes/skills/`，OpenClaw 放其工作区 `skills/` 或用户技能目录，其他 Agent 按各自官方文档加载 Skill 目录即可。工作台不自动替用户安装、创建日程或接通付费搜索；定时搜罗由 Agent 在自己的调度功能里安排。附带 Skill 描述了如何按工作台导出的策略运行外部每日研究。远程智能体需显式设置可达的安全入口；Docker 容器的 localhost 不是宿主机。**把工作台暴露到本机之外前，必须设置访问令牌**：环境变量 `DRAFTDESK_UI_TOKEN`（设置后，所有管理接口强制鉴权，未设置仅适合本机使用）——请求需带 `X-DraftDesk-UI` 头，或 `Authorization: Bearer <令牌>`，或 Basic 认证的密码位；浏览器远程访问建议在反向代理层加 Basic 认证。Agent 专用令牌（接入页创建）不受此门影响。

**部署安全提醒（R10.9）**：`DRAFTDESK_UI_TOKEN` 当前未设——本机 compose 只绑 127.0.0.1 暂无暴露面；**一旦把端口映射改为对外（0.0.0.0 或反代公网），必须先配置该令牌**，否则全部 UI 管理路由（含令牌铸造、全量导出、付费调用触发）对任何能访问端口的客户端裸奔。

同机运行外部 Agent 时，推荐让 Agent 只返回严格 JSON 证据包，由用户在宿主机用提交令牌直接调用 `POST /api/v1/intake` 做预检和提交；这样提交令牌不进入 Agent 对话或容器。网页提取仍受来源的登录与访问限制。外部 Agent 的模型费用和搜索额度由其运行器管理。安装与真实试跑记录见[接入说明](docs/external-onboarding.md)。

## 热词掘金与站点发现

「热词趋势」是独立的海外选题信号台：每日从全源标题流提取实体词（AI 判 💎强相关/○弱相关/🚫圈外三档），再用四路搜索联想展开（Google/YouTube/Amazon/百度/B站）补长尾，另有 34 个工具词根 + 10 个 AI 词根的「词根探针」轮转喂联想（每天 ≤48 词，不打满判定队列），按 region 分层（🌐海外词双职责=英文内容选题+站群候选；🇨🇳中文词=纯内容创作线）。只有 💎强相关词回流挖掘种子（off 词绝不回流）。

三档标尺可在 persona 配置里自定义：`config.persona.termPolicy`（strongHint/weakHint/offHint + redLine 红线词）给了就以它覆盖内置默认，redLine 命中的词由硬规则强制 off（不经模型）；不配则用内置标尺，行为与默认完全一致。判 strong 时顺带产出需求语义三分类 `demandIntent`（tool=工具/产品需求、info=资讯/教程、nav=导航/品牌，标尺同样可经 `persona.intentPolicy` 自定义）与判定判据 `rationale`（命中哪条标准，词库抽屉可见，复核与拍板有据可依），tool 型词直通站群候选池；判 off 的词同步归档（`archivedReason=relevance-off-auto`），不再进任何判定/挖掘队列。自采 SERP 观测有 60 天保质期（`serpCheckedAt`），过期词标「数据待更新」并自动回探针队列重测——与哥飞权威数据的 90 天新鲜度两套并存；词表支持来源层筛选（哥飞注入 ⬆ / 常规采集）。

判定分两层。相关性判定按积压分层扩容（>2000 时每天 16 批 × 200 词），确保数千词的词库能在 48 小时内清完。值不值得做判定对强相关海外词查 SERP 竞争度（vercel/github.io/pages.dev/netlify.app 四类静态平台上有没有同题独立站），结合 obsRatio（近 2 天观测增速 ÷ 前 3 天基线；不足基线的词用保守档，只出可以试试/不值得做）给出三档：✅推荐 / 🟦可以试试 / ⛔不值得做——单位换算/汇率/计算器类「谷歌自答」词上限「可以试试」；每词附派生信号（精确匹配域名数、首页占比、论坛/视频站占比）与结构化竞争观测（`serpTop10Home`=SERP 前 10 首页数、`serpTop3Tier`=前 3 名整站量级档位，Similarweb 免费档 best-effort，存量词不回填）。站群候选按三通道入池：观测（obs≥3 且来源≥2）/ 竞争（strong 且 SERP 竞争≤siteGate 上限）/ 意图（strong 且 demandIntent=tool）；`config.siteGate`（requireStrong/serpDedicatedMax/monthlySearchMin/kdMax/cpcMin，哥飞判断参数内化）是站群标注的唯一规则源——判定 tick 批末自动给达标词标 `siteCandidate=true`（`siteCandidateBy=builtin-gate-v1`），外部 Agent 经 `GET /agent/siteGate` 读同一份规则（规则同源，无需任何人工标注）。

**SEO 数据源（可选增值，默认关闭零调用）**

数据源为哥飞 SEO 工具箱（seo.web.cafe/api，会员积分制，自行注册，仓库不内置令牌），settings 页「SEO 数据源」区块统一管理（开关/令牌/三池额度/授权勾选/连接测试/今日积分消耗）。DataForSEO 不接。适配器为泛化 HTTP 客户端（`core/seo-source.ts`，端点与鉴权集中一处），另备挖词/趋势/竞品站/外链/域名/估值/知识库全量方法面。

- **免费降级路径（默认，零余额消耗）**：关闭/无令牌时全流程走免费字段——strong + 低竞争即站群候选，候选卡打「价值未验证」徽章并附「待查指标」指导深链（/kd/ /ideas/ /serp/ ?kw= 词预填，点开即达哥飞站内）。
- **授权自动链路**（settings 两个授权勾选，默认关）：
  - 指标日更 tick：月累计 metrics 池 30 + 单词观测≥5，批量落三指标 + `gepheiFetchedAt`（90 天过期回退降级），全门槛重判出标、顺带补可注册域名清单、出标后触发出卡。
  - 挖需求采集组：每周日 trends_rising 按词根族轮转注入新词（source=gephei-trends，7/30 天零产出根词自动降频）；每日 keywords/batches 新词发现批次注入（source=gephei-newwords，0 积分免费）；每月 1 日 site_keywords 采标杆站页面（站点发现页「标杆站监控」区块可增删标杆站、高流量页需求词一键入词库候选）；每月 15 日 find_link_prospects 拉卖链站市场快照落外链来源站。

## 应用机会（机会引擎 · 站点发现 · 新站发现）

**热词计划 26 源全谱覆盖**（R9-2）：中文热榜官方接口+聚合补充双路（百度/微博/B站/贴吧/头条/抖音/知乎）、搜索联想中英、Google Trends 六国、开发者社区（GitHub/HN×2/V2EX/掘金）、AI 垂直（HF/reddit×3）、PH 新品、web 搜索；快手维持停用（上游不稳）。**机会引擎平台适配**：watch 候选按策略 platformAffinity 关键词匹配出卡（当前 trend-radar 口径 gzh/xhs-note；适配正则含 tiebuhao=突发/热搜/时间线等），一条命中多平台出多张卡。opportunities 池的整理/合并/遗弃建议由 AI/外部 Agent 巡检产出，人不整理只拍板。

「应用机会」页是三类机会的单入口。**机会引擎**把四类信号统一成机会卡（同词/同证据去重，信号可叠加）：用户抱怨（应用策略的候选与 idea 产物）、新技术/新资讯（产品级变化推演配套缺口——额度监控/状态页/迁移/格式转换）、热词趋势（「推荐」蓝海词 → 站群内容页卡；工具意图词 → 应用卡；alternative 探针词 → 替代缺口卡）与站群候选（siteCandidate 标注词）。每张卡带自动初判（推荐/可以试试/待验证）与一周验证计划，来源标注 auto（内置引擎在 builtin 模式定时与各链路触发）或 agent（外部 Agent 经 `PUT /api/v1/agent/opportunities` 写回，form 六值必填）。机会引擎内按形态（应用/站群）与信号筛选。

**新站发现**（对标新站监控服务）：每日抓 Show HN 与 Product Hunt 新发布站，LLM 批量做中文转译、核心关键词与六类动机判定（冲着关键词/解决自己痛点/满足别人需求/兴趣爱好/商业机会/没说清，标注判定来源=作者原话或推测）；新站核心词命中我们热词库高分词时标「⚠️ 与我们撞词」——竞品早期形态信号。

**站点发现**（判定层顺手产出的独立站池）：按可参考度排序（命中我们高分词 > 非品牌 > 有明确功能），品牌站自动标「不建议做」（规则表：AI 大厂/大厂模式），个人作品集页降权折叠。

## 决策层（审查台）

搜罗产出的每条选题都有两层状态：`quality`（证据可信度，AI 判）与 `decision`（要不要写，人在「审查台」拍板：待决策 → 通过/否决/暂缓 → 写作中 → 已发布，否决记原因）。建议可以多源——内置 AI 与外部 Agent 各写各的 `suggestions`，互不覆盖；拍板只能一个。否决与发布自动消费对应热榜条目。

选题按「平台 × 题材」双标注：九平台（`gzh` / `tiebuhao` / `xhs-note` / `xhs-video`（后置）/ `threads` / `x` / `facebook` / `instagram` / `linkedin`）与六题材（AI 新技术/新资讯/开源工具/自研产品/个人思考/社会热点）；题材可点改（LLM 初标的人工纠偏口）。**拍板按平台分开**：每条选题按平台徽章各带独立状态，点徽章循环拍板（同一条选题可以「公众号通过、小红书暂缓」），`perPlatformDecision` 记录各平台决策、聚合 `decision` 取最前进正向状态；同题多条聚合不再一键连拍全组，各平台互不影响。

草稿全程可见：pending 的选题只要有草稿就显示「有草稿」徽章与只读预览（Markdown 渲染），通过后开放编辑；大纲抽屉同时展示内容结构、写作要点与数据源。

产出兜底链按消费执行方联动：external 模式由外部 Agent 对 approved 选题写第一版大纲（keyPoints/outline/draftBody，提示词矩阵见 `skills/prompts/outline-matrix.md`，接入指引见[外部 Agent 接入指南](docs/agent-integration.md)）；builtin 模式由内置 AI 在每日 01:00 日批中自动为 approved 选题按「平台模板 × 题材角度」生成第一版大纲并推进到「写作中」（R10.33 起全部日粒度任务随日批一次跑完，白天循环静默）。手动添加选题、人设配置（AI 个性化判断输入，可编辑）与内置 AI 参与开关 aiPolicy（triage/outline/draft 三档 off|cheap|full，经 suggest scope 令牌经 /api/v1/agent/clusters|outlines 写回）都在「审查台」页。人拍板走页面，Agent 走 `/api/v1/agent/decisions*` 与 `suggestions`（read scope 即可，建议不改变人的拍板）。

## 数据与边界

- 应用机会、会话与外部原始证据始终私有。公开接口只返回显式公开且通过检查的资讯与选题投影。
- 本版只绑定 127.0.0.1，没有多用户登录、支付和公网租户隔离。不能直接作为多租户 SaaS 上线。
- 不自动爬取受登录/验证码/付费墙保护的公众号及国内平台。可用已授权外部工具、RSS 或手动证据导入补充。
- JSON 工作数据导出不含密钥。备份已自动化：每日快照在 `backups/`（14 份）、迁移前保险丝在 `data/snapshots/`（3 份）。手动备份需先 `docker compose stop`，再复制 volume 中的 `draftdesk.sqlite`；不要在写入中直接复制单个 sqlite 文件（含 WAL 时只拷主库会丢数据）。
- 旧版浏览器选题在首次访问同一地址时自动导入“我的选题库 / 旧版选题”，保留原字段，不删除旧浏览器存储。模型配置通过迁移脚本转入新数据库。
- 模型调用前按输入 UTF-8 字节和最大输出保守预留；成功返回用量后按回传 token 加缓冲结算并释放未用预留。没有可靠用量、调用失败或取消时保留预留，防止重试绕预算。搜索次数另有限额。这是运行限额，不是人民币账单。
- 搜索与模型请求无自动无限重试；进程中断任务会在租约过期后标失败，而不是自动重复扣费。所有运行版本与中间分析可导出。
