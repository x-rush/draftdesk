# 大纲选题句范例（标题即角度，非主题词）

> R10.35 起：**一个选题一条大纲**。标题写选题方向，`platforms` 标适合平台，
> 平台差异写进 `recommendation`——不再为每个平台各写一份大纲。

## 反例 → 正例

| 主题词式（不合格） | 选题句式（合格） |
|---|---|
| AI 播放器发布 | 换掉传统播放器前，先看这三个本地 AI 功能值不值 |
| 编程助手更新 | 免费档也能跑多步任务：编排功能迁移指南 |
| 分成政策调整 | 第三轮分成调整后，小创作者定价公式的三处修正 |
| API 限流上调 | 限流翻倍后，你的自动化教程该加的那段重试逻辑 |

## 一条大纲的完整写法（推荐）

```json
{
  "clusterId": "clu-xxx",
  "platforms": ["gzh", "xhs-note", "tiebuhao"],
  "recommendation": "主投公众号做完整论证（三个场景实测对比），小红书切片成「三问三答」清单笔记带收藏钩子，贴图号出 4 张图卡（首图即结论）。Threads 不出——英文受众对该硬件话题无共鸣。",
  "contentType": "长文",
  "title": "换掉传统播放器前，先看这三个本地 AI 功能值不值",
  "outline": ["问题：在线播放器的三个具体卡点（附实测耗时）", "方案：本地 AI 功能的三个可用场景", "边界：哪些片子本地跑不动", "决策：三种人该选哪个"],
  "keyPoints": ["实测数据来自 XX 对比", "本地跑不吃带宽"],
  "evidenceRefs": ["<组内真实 url>"]
}
```

**推荐建议要讲清三件事**：主投哪个平台（为什么）、其余平台怎么适配（形态/钩子/篇幅）、
哪个平台明确不出（理由）——这一句替代了过去的「每平台一份大纲」。

## 平台形态（写进推荐建议，不用再各写一份大纲）

### gzh（完整论证）
- 标题：判断句或承诺句（「换掉 X 前，先看 Y」/「免质保也能做的 Z」）
- outline：3–8 项递进，每项写具体要展示的材料/例子/问题——禁止「背景/意义/展望」空骨架

### tiebuhao（图卡组 3–6 张）
- 首图即观点；每张文案 ≤54 字；视觉关键词 3–5 个
- 例：首图「本地 AI 播放器真比在线快？」→ 卡片依次给三个场景对比 → 末卡给选择清单

### xhs-note（清单体/教程体）
- 标题带可收藏价值点（「一图流」「避坑清单」「保姆级」）
- 例：一图流：Win/Mac 隐藏截图快捷键大全（工具教程类）

### threads（英文短评 ≤500 字符）
- 中文选题的英文短评改写，不是新选题；观点句开头
- 例：Local AI video players just killed my last reason to stay online. Three scenes where the speed gap actually matters. 🧵

## 跨日去重意识

写题前自问：**昨天/前天是否已有同事件组出过题？**
- 有且无新进展 → 不出题，在回执 note 里注明「事件线 X 连续第 N 日，无新进展」
- 有且有新进展 → 出增量题，标题体现进展（「第三轮调整后…」而非重写首轮）
