# 来源与相关性判断

先按用户目标确定材料价值，再聚类；不要先凑满数量再找理由。以下判断用现有 summary、contradictions、missing、excluded.reason 表达，不增加输出合同外字段。

## 不同来源能支持什么

| 来源 | 可以支持 | 不能自动支持 |
|---|---|---|
| 本人/产品官方公告 | 该主体宣布的版本、开放范围和条款 | 实际效果领先、所有人适用 |
| 独立实测 | 测试所用条件下的结果 | 未测试的语言、任务或套餐 |
| 用户原话 | 此人在此情境的经历或要求 | 人群规模、普遍付费意愿 |
| 热榜与仓库指标 | 来源特定时间口径的排序或数量 | 持续增长、国内需求、收入 |
| 聚合站/转载 | 发现线索和找到原始出处 | 独立复核、全文已读 |

sourceType 是输入标签，不是已认证的权威性。核对 URL、署名、材料内容是否相符。跨域转载同一公告仍为一个根来源；同站不同人的独立报告也不能只因域名相同就当成同一人。

## 保留、暂存、排除

- 保留：能连接到明确的读者任务变化，例如导出方式、成本、限制、可用性或判断方法。
- 暂存：相关，但关键条件未提供。missing 说明缺哪种原始资料，能改变哪个判断。
- 排除：只剩融资、估值、跑分或名人关注度，没有具体任务影响；说明理由，允许空结果。
- 指标与文字冲突时保留两者，记录各自时间和适用条件。未查明时不选更吸引人的说法。

## 材料不足的处理

truncated 表示材料已被裁剪；看见开头和结尾不代表中间已经核实。headline 不能支持完整使用教程。价格、地区、版本缺失时不要用常识补齐。需要补搜时在 missing 写具体问题和可核查出处；当前阶段没有搜索工具，不声称已补查。

例：官方只宣布“企业套餐新增导出”。可以保留“企业用户流程变化”，不能改成“所有人免费可用”；普通个人读者策略下可能应排除或作为套餐避坑线索。
