# 研究 Skills 评测

## 1.2 固定对照与评分

新增 `baseline-v1.1/` 保存本次优化前的六个研究阶段入口与参考规程。比较 1.1 与当前版本：

```sh
docker compose exec worker npm run eval:skills -- --live --case official-limits --baseline-v1.1
```

同一案例使用相同模型、证据、观察日期和 12000 最大输出预算，Qwen 的思考预算相同。提示词长度不同，因此实际 token 不强行伪装相同；每组仍受 160000 保守预留总上限和工作台每日限额约束。命令默认不会发起真实调用，必须显式 `--live`。这六个 1.1 基线不包含讨论/提交技能。

`report.json` 同时记录耗时、已回传 token、保守预留以及三项机器诊断：引用 ID 有效率、原话精确匹配率、事实陈述引用覆盖率。它们不衡量事实蕴含，不能取代人工判断。

`review.json` 增加五个固定盲审维度：读者/任务相关性、关键事实支持、行动性、反证与未知项、没有虚构需求。每项 0–4 分：0 相反或虚构，1 重大遗漏，2 部分满足，3 满足，4 满足且有明确反证与可复现行动。每项填写原文依据，然后运行：

```sh
docker compose exec worker npx tsx scripts/summarize-evaluation.ts data/evaluations/<run-id>
```

评分和依据缺失时总分保持 null；不会把未测试写成零分或满分。输出保存到原评测目录 `summary.json`。没有合格推荐可以是正确结果，按案例标准判断，不用产物数量评优。

这些样例是虚构的受控材料，不是真实新闻，也不会进入选题库。比较的是同一模型在固定证据上的专项判断；不代表真实搜索覆盖率或整条研究流程成功率。

## 真实模型对照

先在工作台配置百炼连接，然后逐例运行：

`docker compose exec worker npm run eval:skills -- --live --case official-limits`

一次只接受一个 case：旧版 v1 与当前版各一次调用，无自动重试，无搜索。最多两次调用，token 预留合计上限 160000，且受工作台每日上限约束。原始输出和用量在 `data/evaluations/<run-id>/`；只发送虚构评测材料，不发送用户选题和聊天历史。真实调用需可用凭据，本次没有预填密钥。

先看 `report.json` 的随机 A/B 输出，用 `review.json` 逐条填写满足/不满足/无法判断及具体原文依据；再查看 `answer-key.json` 解盲。机器检查单独列出，不能代替业务评审。空结果是否合理要结合场景，不能把有输出当成成功。评测标注未做时保留 null，绝不自动显示通过率。

建议在两个以上独立运行中重复同一案例，关注事实支持、相关性、可执行性、遗漏条件与成本。若新版不能稳定改善，保留旧版本或针对失败点修改后重测。不要因为一个样例更长、更好看就判定新版胜出。题目和隐藏标准不发送给模型作为答案提示。

当前范围：专项阶段 A/B 测试；全流程工程测试另在 tests/workbench.test.ts。真实模型结果尚未产生前，不得宣称内容质量已提高或达到商用验收。
