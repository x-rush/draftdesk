# OpenClaw / Hermes 接入实测（2026-09-24）

本记录只评价一次受控小样本：每个 Agent 搜索 AI 资讯，最多提交两条证据，`drafts=[]`。它不代表连续运行成功率，也不能证明完整选题质量。测试使用项目的 Docker 容器、SearXNG 和工作台个人实例，提交令牌只保存在宿主机忽略目录。

| 环节 | OpenClaw | Hermes |
| --- | --- | --- |
| 搜索网络 | 容器内 SearXNG 返回结果；官方 SearXNG 插件已启用 | 容器内 SearXNG 返回结果，首轮搜索返回 10 条线索 |
| 第一轮障碍 | 复用主会话并与已运行 Gateway 的 `--local` 模式冲突；随后一次宽泛任务在 180 秒内未完成 | `web_extract` 不支持 SearXNG 搜索后正文提取；单次命令禁止通过脚本写文件 |
| 调整 | 使用独立新会话、关闭额外思考并把检索限定为一次；仍须先预检结构 | 使用已有搜索结果，最终只输出一个 JSON 证据包；由宿主机适配器保存与提交 |
| 协议预检 | 日期仅有 `YYYY-MM-DD` 被严格 ISO 时间检查拒绝；适配器改为省略可选的 `publishedAt`，保留来源摘要 | 证据包和受信令牌预检通过 |
| 工作台结果 | 1 条官方页面证据、`pending-review` 回执 | 1 条官方页面证据、`pending-review` 回执 |
| 本次模型用量观察 | 宽泛失败轮报告约 225935 token 总量（包含缓存用量）；新会话一次无匹配约 42889 输入 / 1154 输出，随后目标查询约 5685 输入 / 726 输出 | 首次工具轮约 24000 输入 / 1700 输出；续接整理另有用量 |

这两份证据都没有直接生成草稿。该官方公告样本与普通创作者的日常内容需求关联较弱，搜索连通和结构化成功不等于选题质量达标。工具回传的用量与零费用字段不能替代供应商账单，尤其是超时调用；外部 Agent 的花费不受 DraftDesk 内部模型预算约束。

本轮把 Docker 路径改为“Agent 搜索并输出严格 JSON → 宿主机 `sync-result.ps1` 预检 → 使用独立收件令牌提交”。令牌不进入 Agent 提示词或容器。向导和文档明确独立会话、一次搜索小样本、SearXNG 仅搜索、日期精度和无结果时停止。正式研究仍需要另行检查正文来源、时间、个人影响与草稿引用；下一次比较应在同一证据、相同查询次数和供应商账单口径下进行。
