# 数据源与研究策略配置

DraftDesk 社区版是个人自托管工作台。数据源负责提供线索；只有在研究策略中勾选、且数据源本身启用后，任务才会读取它。添加来源不会自动扩大模型预算，也不保证相关条目进入 AI 分析。

## 第一次配置

1. 在「模型与设置」填写百炼模型的 Base URL、模型名和 API Key，测试连接。密钥保存在服务端，不填进研究提示词或 Git 仓库。
2. 如需网页补查，在同页填写 Tavily Key 并点「测试搜索」。Tavily 用于网页搜索与定向补证；热榜来源不依赖 Tavily。
3. 在「数据源」逐项检查说明。DailyHotApi 聚合来源可点「检测连接」，测试不调用模型、不入库。失败的来源先保持停用。
4. 在「研究策略」分别为资讯选题、热词、应用机会选择来源和关键词，查看「搜罗计划预览」，先手动运行。策略中的最多证据数是送入 AI 的上限，并非采集上限。
5. 在「每日发现」查看推荐结果、待观察线索与采集覆盖。来源失败、关键词筛除、证据名额不足是不同原因；调整后再运行，不把零推荐解释为全网没有机会。

## 来源类型与边界

| 类型 | 配置入口 | 用途与边界 |
| --- | --- | --- |
| 官方 RSS / Atom | 数据源 → HTTPS Feed | 厂商公告、产品更新。填写公开的 HTTPS 地址；正文是否完整取决于 Feed。 |
| Google Trends 地域榜 | 数据源 → 地域代码 | 观察指定地域的近期搜索话题。不同地域和分桶指标不能混算。 |
| 官方热榜 | 数据源 → 已核对入口 | 百度、微博、GitHub Trending、Hacker News。微博匿名访问可能受限；失败记录在运行说明。 |
| DailyHotApi 聚合榜 | 数据源 → 聚合平台 | Docker 内部服务读取公开榜单。只把标题、原平台链接、同平台热度和榜单更新时间作为线索；不当作官方事实证明。 |
| GitHub 仓库搜索 | 数据源 → 搜索条件 | 找活跃项目；Stars 和更新时间不是付费需求。 |
| Tavily 网页搜索 | 数据源 + Tavily Key | 按策略搜索并补关键结论；搜索摘要不等于全文或事实认证。 |
| 创作者活动中心 | 「创作活动」单独流程 | 登录后的活动规则、资格、截止时间。它与公开热榜不同，参见[四平台活动采集](creator-activities.md)。 |

聚合器为 [imsyy/DailyHotApi](https://github.com/imsyy/DailyHotApi)，在 `compose.yaml` 中固定镜像摘要，不对宿主机开放端口。代码的 MIT 许可不授予各平台内容转载或商业数据使用权；本工作台保存有限的个人研究线索，不抓取榜单全文。对外运营前应重新核对各平台条款与数据授权。

本机验证结果及失效情况见[热榜来源说明](hotlist-sources.md)。目前知乎、抖音、头条、贴吧、掘金可读；B站出现过超时，微博、快手上游仍异常。数据源页的「检测连接」反映检测当时的状态，不能替代持续监控。无效原平台链接、空榜和超过两小时未更新的榜单会拒绝入库。

## 避免漏掉机会

来源目录不等于一次任务的来源清单。默认热词策略只勾选百度热搜、美国 Google Trends 与网页搜索，其他平台需要按目标受众加入策略。单策略最多选择 12 个来源；默认最多 18 条证据入模，应用机会默认最多 3 条产物。用户可调整预算，但大量低质量标题同时入模通常会挤掉真正需要核实的材料。

内置采集先按时间、域名、排除词、方向词和热词关键词筛选，再按来源轮流选证据。`Vibe Coding`、`vibecoding`、`氛围编程`、`AI 编程`以及常见 AI 视频表达会合并匹配；其他同义表达仍可能遗漏。最近一次内置运行的标题与原链接会进入「待观察线索」，最多记录每来源前 100 条，仅保留 14 天；「采集覆盖」显示读取、匹配、入模和失败数量。候选标题不自动成为推荐，也不证明完整需求。外部 Agent 的证据按收件回执和运行记录查看。

## 故障排查

- 「检测连接」失败：先看错误和来源更新日期；上游验证、超时或结构变化都可能导致失败。保持停用并选其他来源，不尝试绕过验证码。
- 抓到许多但入模很少：检查关键词、方向词、限定域名、时间窗口和证据上限；在「待观察线索」勾选「包含规则筛除」查看具体原因。
- 入模但无推荐：打开运行记录中的研究结果说明，查看模型筛除、缺少一手证据或质量审核结果。
- 想比较“增长”：单次热榜热度是平台内即时值；没有相同地区、单位、周期的连续原始数据，不计算增长率。
- 需要新的公开来源：可添加 RSS/Atom；其他平台先验证可用入口及使用条件，再开发适配器。不要把登录 Cookie、API Key 写进公开仓库。
