# 四平台官方活动采集与分析

1. 在自己的 Chrome / Edge 登录四个平台的创作者中心。Codex 内置浏览器与 Chrome / Edge 不共享登录状态。
2. 下载当前 `activity-collector.zip` 并解压，在浏览器扩展管理页开启开发者模式、加载已解压的扩展；当前版本为 1.6.8。扩展需要本机工作台连接权限，浏览器可能要求确认。
3. 插件默认连接 `http://127.0.0.1:5173`。如果工作台使用其他本机端口，在插件中改为 `http://127.0.0.1:端口` 或 `http://localhost:端口`，点击「检查连接」。只接受本机 HTTP 地址；连接时可能在后台打开一张工作台标签页。默认勾选「采集完成后自动发送」，可取消。
4. 在创作者中心首页或其他官方页面打开扩展，输入目标关键词与扫描页数，点击「打开活动页并采集」；扩展先导航到官方活动中心，等待列表加载，再启动采集。默认关键词涵盖 AI、AIGC、AI 视频、Vibe Coding 与 AI 编程。四平台各执行一次；扩展按平台保存结果。抖音目前只读取当前显示月份。
5. 采集完成后，插件在后台把该平台活动包送到本机工作台；「已开始发送」只表示任务启动，必须等插件显示「已送达」或在工作台看到新快照才算成功。上传设有超时，失败或消息通道中断后可重试，原始包不会丢失。工作台「创作活动」每 5 秒读取最新送达的四平台包并合并待核预览；送达不创建研究任务、不调用模型。发送失败时在对应平台点「发送本次结果」重试；切到工作台或其他标签页后，也可点「发送已保存的 N 个平台结果」。也可用「导出本平台采集结果」保存 JSON，再在工作台一次选择最多四份文件导入。
6. 原始快照保存标题、原始摘录、时间原文、来源链接、采集时间和当前扩展提供的扫描范围；历史快照仍可查看。采集目标是近期可考虑的活动，不是翻完历史档案。工作台只接受包含扫描范围和停止策略的当前格式采集包，旧格式不会导入、展示或送入 AI；如发现旧格式提示，请重新采集。预览分别统计「可直接分析」「相关待核线索」「其余记录」，默认先列目标活动；「全部原始数据」仍可查看每一条及排除原因。
7. 点击「对相关原始线索做 AI 初筛」只把命中关键词、未确认过期的最多 12 条送给模型。结果单独保存并展示相关性、缺失证据和条件性创作方向；它不是活动仍有效或账号可参与的证明。待核线索可点「核实这条」，将标题、地址和已采文本带入单条规则表单。须回到官方详情补齐含年份的截止日期与规则正文；不要把列表月日或采集日期当成投稿年份。单次正式研究最多接收 24 条合格活动和 8 个目标关键词。只有手动点击初筛或正式分析按钮才会调用模型。

扩展对命中目标关键词的线索尝试读取可见详情，不点击报名、领取或发布按钮。无可核实截止日期、已过期以及只有摘要的活动不进入付费模型分析。页面只给出月日且没有明确年份时不会猜测年份；即使页面展示在活动中心，也只能作为待核线索。跨年或平台延长时间需要人工查看规则。小红书侧栏中的官方规则 iframe 会等待最多约 4 秒再读取；只有短简介时仍标记为摘要。抖音日历弹窗若包含完整规则和可核对日期，可进入分析，但因为没有单条活动链接，产物仍需按标题到官方活动中心复核，不会直接成为通过审稿的推荐。页面变动、登录过期和验证会产生错误或缺项，不能以 0 条解释为没有活动。

## 采集路径与当前边界

| 平台 | 已核对的列表结构 | 详情与日期处理 | 翻页范围 |
| --- | --- | --- | --- |
| B 站 | 已登录页面中的 `h2 a[href*="/blackboard/era/"]` 和 `.event_status`；列表是客户端渲染，不能直接 `fetch` 页面 HTML 当作列表 | 在官方活动详情页读取规则；年份来自列表日期 | 点击 `.flip-left .next-page`，最多 5 页；若已确认本次列表按开始日期由新到旧，且连续两页的活动截止日全部已过，则提前停止并记录原因。长期活动可能跨过这个边界，不能称为全平台无遗漏 |
| 小红书 | `/new/events` 的 `.card-box`、`.title`、`.desc`、`.time` | 打开详情侧栏，读取可访问的官方 `fe.xiaohongshu.com/ditto/vincent/` 规则 iframe；日期仍以规则原文为准，读取失败时只留摘要 | `.d-pagination-page-content`，最多 5 页 |
| 抖音 | 创作者中心活动日历的活动条目 | 读取活动弹窗；当前显示月份的年份来自日历标题；没有单条链接时保存活动中心 URL 和标题，结果须复核 | 当前月份；需要用户切换月份后再执行 |
| 快手 | 创作者中心活动列表卡片 | 只尝试打开活动标题关联的详情，不点「去领取」；拿不到官方详情时只作摘要 | 当前列表向下滚动，最多 5 屏 |

每个平台最多保留 100 条线索，分析前由工作台再次按截止时间、规则完整度及用户关键词过滤。直接同步只传活动包，不传 Cookie、密码或平台账号资料；活动包保存在本机 DraftDesk 数据目录中。JSON 导出仍保存在用户本机；浏览器运行期间需保持官方页面登录状态，验证码或页面结构变化需要人工处理。手动导入单条规则时，工作台要求填写从正文核对的投稿截止日期，已过期或原文不含该年份与日期时不会启动付费分析。

扩展通过 Chrome / Edge 当前已登录页面工作，不读取 Cookie。活动规则仅在用户点击运行 AI 分析时发送给自行配置的模型供应商；自动送达本机工作台不会触发模型调用。这不是无人值守的服务器定时采集。直接同步仅支持本机工作台，远程公开实例应使用单独设计的身份认证与 HTTPS 接入。来源代码在 `public/activity-collector`，打包文件是 `public/activity-collector.zip`。

2026-09-25 在内置浏览器复核了四个平台的已登录页面。B 站活动列表是客户端渲染；小红书活动列表使用 `.card-box`；抖音当前月份可见 `.douyin-creator-common-calendar-event-item`，点击后显示含活动时间、玩法和奖励的 `[role="dialog"]` 侧栏；快手活动卡片使用 `.list_item`，含标题、简介与月日时间。快手列表没有明确年份，必须在详情补到年份；抖音没有单条活动链接，产物须按标题复核。扩展在用户 Chrome / Edge 的四平台端到端操作、快手详情新标签捕获、抖音跨月和登录失效恢复仍需实测；不能宣称四个平台稳定全量采集。
