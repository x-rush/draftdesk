# 低评分能力优化 · 2026-09-23

本轮针对验收中的热词 4 分、应用/人物 5 分、资讯/选题 6 分。原有真实样本评分不因工程改动自动上调。

## 已实现

- 所有产物详情增加“证据缺口与下一步”，展示材料候选、缺失项、核对动作及可复制补查词。使用原证据实时计算，旧记录也可查看，不修改历史内容或审核结论。
- 应用：检查社区材料中的问题原话是否逐字引用，单有社区 URL 不够；分别展示替代方案与实际付费行为线索。线索不是需求认证，付费未知的机会可以保留，但不作为已通过检查的机会。
- 人物：检查姓名与一手材料关联；公开渠道须对应具体采集页面，不能按相同域名或同名合并。保留 URL 查询参数，避免混淆以参数区分的账号。
- 资讯/选题：检查一手来源，价格/开放/发布时间等关键事实要求原文锚点；锚点只能证明原话存在，语义关系仍交给审稿和人判断。
- 热词：地域未知不计算增幅；榜单名次不换算热度增长。原始指标和用户搜索意图分开检查。未补造历史点，未新增国内热榜连接器。
- 生成前补查：即使整理模型没有报告缺口，缺少用户问题、一手资料或原始指标也会进入补查候选，共用原有最多两次补查及总查询/证据预算；外部证据重试仍不额外搜索。
- 审稿上下文加入程序材料检查，确定性缺口不能被模型的 pass 覆盖。关键词查询减少无关词堆叠。网页搜索配置为 official 不再将任意返回网页标为官方；只从用户已启用的官方 RSS 配置识别同主机候选，仍非真实性认证。
- 五个研究/审稿 Skill 更新为 1.3.0，遵循 skill-creator 的针对性迭代方法；保留原有来源声明。内置流程与下载包都会使用新版。已安装到外部 Agent 的旧包需要重新安装，未宣称已自动更新外部 Agent。

## 验证

54 项自动化测试通过；新增反例涵盖宣传冒充问题、伪造引文、同名/同域不同账号、关键事实无原文、未知地域和排名增幅、官方来源标签滥用，以及模型漏报缺口/审稿误判的整条管线。供应商均隔离模拟，测试无需真实密钥。修复了旧研究升级测试依赖环境密钥的缺陷。

五个 Skill 均通过 quick_validate.py。生产构建包含 TypeScript 校验。

对实际工作区 14 条产物执行 scripts/audit-evidence-readiness.ts，只读、无模型调用：3 条应用均缺少满足检查的用户问题原话和付费行为；2 条热词均缺原始指标与具体问题线索；1 条人物缺一手身份关联。8 条资讯/选题缺被标记为 official 的正文材料。这是当前材料与标签的缺口，不能据此断言原网上不存在相应资料。当前无可计算同口径变化的指标对。

浏览器已打开实际应用创意，验证缺口、行动和补查词可见。已通过测试并部署本地 Docker。
